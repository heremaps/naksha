## Suspected issues (not verified)

- **JS/PLV8 write path:** `PgWriter` issues `SAVEPOINT` / `ROLLBACK TO SAVEPOINT` as plain SQL, which PLV8's server-side interface normally rejects, and the JS connection's `rollback()` does nothing. A failed first request could leave partial writes in the transaction. Deferred, but nothing blocks the path.
- **`PgDatabase.kt:1625`:** `oldCc as? Int ?: 0` resets the change count if the cursor delivers a `Long`.
- **`new_version` (`PgDatabase.kt:414`):** commits the session connection, which would silently release a transaction lock taken before the first write.
- **View tuple loading:** `NHSpaceStorage.getId()` returns `"NH_ADMIN_STORAGE_" + psqlId`, whose number will not match tuple database numbers, so `ViewLayerCollection.getByTupleNumber` may always fail. The path was previously unsupported.
- **View PATCH:** inherited detection hard-codes `storagePriority == 0` (no main-code caller of `withWriteLayer` found), and depends on the read response staying a `ViewSuccessResult`; a rewrapping handler would silently fall back to UPDATE/UPSERT.
- **Behavior changes to confirm as intended:** PATCH preprocessing now runs on the merged feature, so tag add/remove parameters reach the stored state; `AuthorizationEventHandler` now authorizes all write requests, which rejects read-only users on space-triggered collection writes.
- **Unsafe publication:** `Tuple._id` and `Write` id caches are published without synchronization while `Id` has non-final fields.

## Checked and found sound

Identifier and literal quoting (`PgUtil.quoteIdent` / `quoteLiteral`); the verified name classes and their byte budgets and ownership checks; DDL built only from quoted identifiers and validated integers; catalog queries qualified with `pg_catalog` and bound parameters; tablespace, index method and opclass sources; `PgRows` aliases; jsonpath escaping; internally generated savepoint names; ACLs and pinned search path on `naksha_maintain`; credential-free `PgLocalConfig` schema comment; the `common.js` import rewrite; Hub catalog override (clients cannot redirect writes via late binding); server-side view PATCH provenance with bounded retries; transaction boundaries, lock order and positional result matching in the `rows_*` functions; no tracked secrets (`vault/` is gitignored except its README; committed docs contain only placeholders).

## Missing test coverage

- Cross-instance delete followed by re-create with a different layout or history mode; UPSERT after delete; reload-versus-delete cache races; `getCollectionById` on a deleted catalog inside an open write transaction.
- Colliding catalog/collection ids; refusing to drop or reuse non-Naksha schemas and tables.
- `runParallel` with uneven completion; concurrent `useConn`; concurrent first access to `validatedMembers`; `AbstractStorage` re-init while other threads read.
- HTTP mapping for `ILLEGAL_ID`, `COLLECTION_NOT_FOUND`, `MapNotFound`, `UNSUPPORTED_OPERATION`; whether error causes reach HTTP bodies.
- `NakshaContext` initialization in Node; the PLV8 write path (savepoints, rollback, search path).
- `ListProxy.splice` with several elements; `TupleNumber.compareTo` with large signed numbers; PATCH through a handler that rewraps the view read response; `ViewReadSession.loadTuples` with `NHSpaceStorage` layers.
